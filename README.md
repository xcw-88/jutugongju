# 聊天软件截屏助手

Windows 10（1809 及以上）/11 x64 桌面工具，完成「微信或钉钉聊天窗口 → 框选 → 向上或向下滚动截图 → 编号 PNG → A4 PDF」流程。当前版本为 V1.3.1，所有截图和说明均在本机处理。

## 直接使用

双击 `聊天软件截屏助手.exe`（构建输出位于 `dist/聊天软件截屏助手.exe`）。无需安装 Python。请把程序放在有写入权限的普通文件夹，例如桌面或文档目录。

1. 打开电脑端微信或钉钉，进入需要整理的聊天。**向上采集从较新一端开始；向下采集从较早一端开始**。
2. 启动程序后出现遮罩。按住鼠标左键拖动，框选消息区域，松开确认。建议包含聊天对象、时间及完整消息宽度，避免包含输入框。Esc 或右键取消；主界面可再次框选。
3. 填写证据名称、材料标题、对象、身份、时间范围和证明目的。证据名称为必填；材料标题默认为「项目工作沟通记录」，可修改，留空则隐藏。其余说明空字段在 PDF 中显示「（填写）」，程序不推断内容。
4. 在「采集设置 → 滚动方向」选择向上或向下，再设置等待时间、滚轮幅度和截图数量上限。**先设置 3 张试采**，检查相邻画面是否有足够重叠。默认加载等待 3 秒、向上滚动 3 格、最多采集 20 张、开始倒计时 5 秒。
5. 点击「开始采集」。工具最小化；在倒计时内切换到微信或钉钉并保持聊天窗口在前台。程序等待图片加载后保存第一张，再按所选方向滚动，等待后保存下一张。最后一张之后不再滚动。
6. **按 Esc 停止**。也可以恢复工具窗口点击「停止采集」。移动鼠标至主屏幕角落可触发 PyAutoGUI 的滚轮保护。停止后保留已经完成写入的截图。
7. 默认在连续两次滚动、等待后画面完全未变时自动结束采集并返回主界面；达到数量上限或主动停止也会结束。上述情况默认自动生成 PDF；异常停止时先检查原因，再点击「生成 PDF」。可取消自动生成，检查原图后手动导出。
8. 双击截图检查原始像素，打开 PDF 预览。打印时选 A4 竖版，先试印一页。

## 保存文件

默认输出位置为 EXE 同目录下的 `output`，可在界面修改。文件夹无写入权限时请选择可写入位置。

```text
output/
  证据名称/
    001.png
    002.png
    003.png
    证据名称项目工作沟通记录.pdf
    manifest.json
  证据名称_02/
    ...
```

编号表示**实际采集顺序**，不在 PNG 上叠加文字。同名采集会新建 `_02`、`_03` 等目录；再次导出会新建带编号的 PDF，不覆盖已有材料。

`manifest.json` 记录本次说明、坐标、采集参数、采集时间、PNG SHA-256 校验值、运行结果和 PDF 页码对应关系。导出时检查文件是否缺失或被修改。校验值用于发现文件变化，不用于判断证据有效性。

区域、采集设置和上次填写的材料标题保存于 `%LOCALAPPDATA%\EvidenceCapture\config.json`，错误日志在同目录的 `application.log`。证据说明保存于每组证据目录，不提供 V2 的模板管理。

## PDF 排版

- A4 竖版，第一页为「证据材料 / 自定义材料标题」，包括对象、身份、时间范围、证明目的及证据名称。材料标题同时用于截图页标题及 PDF 文件名；留空时隐藏材料标题，文件名使用证据名称。
- 超长说明自动续页，避免截断；普通说明在第一页内完成。
- 后续每页放一张完整截图，等比缩放、保留全部像素、无 JPEG 有损压缩。PDF 不添加原图文件名和页码。中文字体来自本机宋体/黑体/仿宋并嵌入 PDF。
- 切换方向时自动调整默认 PDF 页序：**向上采集使用反向顺序，向下采集使用 001 → 002 → 003 的采集顺序**，便于较早画面在前。可手动更改页序；打开已有证据目录时按该目录记录的方向或上次导出页序恢复。程序不识别聊天时间、不重排消息。
- 打开已有证据目录时，选择含 `001.png` 等文件的具体子目录，可修改材料标题和说明重新导出；优先恢复上次导出的说明。旧 PDF 需要重新生成才能应用新版排版。支持本工具的编号 PNG 文件夹，不包含钉钉 JSON/HTML/TXT 导入。

## 采集与打印边界

- 使用屏幕上实际显示的内容；钉钉最小化、电脑锁屏或显示器布局改变时无法正常采集。切换前台窗口、移动或调整目标窗口大小时停止；区域中心和四角检测到其他窗口遮挡也会停止。小面积遮挡、同窗口内切换聊天无法可靠识别，采集时请不要操作电脑。
- 图片懒加载采用可调整的固定等待，不自动判断图片是否完成加载。网络慢时增加至 5–10 秒；必要时先在钉钉中展开或加载图片，再重新采集。
- V1.2.1 将每格滚轮分别发送，格间保留约 0.12 秒处理时间，改善微信对单次大幅滚轮输入只移动一小段的兼容性。滚轮「格数」受聊天软件和 Windows 设置影响，不等于固定像素。升级后先用 3 张试采，检查相邻画面重叠；出现间隔时减少滚轮幅度重采。程序保留重复截图，不去重、不拼接、不按关键词筛选，不保证自动覆盖完整历史。
- 到达顶部（向上）或底部（向下）时，连续两次滚动并等待后画面完全未变，默认自动结束并保存，返回主界面。用于确认未变化的截图全部保留。该判断也可能由滚动未生效或加载过慢触发，需检查结果；动态内容可能使画面一直不同，此时仍受数量上限限制。可取消「滚动后画面连续两次不变，自动结束并保存」。
- 保留原始 PNG 不等于可以提升原本模糊的画面。建议扩大聊天窗口、让文字和图片在屏幕上清楚可辨，再框选消息区；过宽选区打印后可能使文字变小。原图检查和试印不能省略。
- 支持每次在单个显示器内框选；计算考虑屏幕缩放和负坐标。跨显示器的区域请分次采集。改变分辨率、缩放或显示器排列后重新框选。
- 钉钉如以管理员身份运行，普通权限程序的滚轮输入可能受系统限制，优先使用普通权限运行钉钉。程序自身无需管理员权限。
- 若进程被强制结束，已经保存的 PNG 仍在；日志可能停留在 `running`。重新打开目录检查文件后再导出。如果最后一张未被记录，导出校验会提示不一致，需检查恢复，不会静默忽略。

## 开发与打包

开发使用 Python 3.14、PySide6、mss、PyAutoGUI、Pillow、ReportLab 和 cryptography；本次构建环境为 Windows 11 x64。最终用户只需 EXE 和为该电脑签发的授权码。

```powershell
python -m pip install -r requirements-dev.txt
python EvidenceCapture.py
python -m pytest -q
python -m PyInstaller --noconfirm EvidenceCapture.spec
```

也可运行 `./build.ps1`。构建结果为 `dist/聊天软件截屏助手.exe`，单文件，包含 Python 和依赖。首次打开会在系统临时目录解压依赖，可能需要数秒。中文字体使用 Windows 自带字体，未将 Windows 字体文件单独分发。

启动参数 `--no-auto-select` 可跳过启动遮罩，用于调试。`python -m tests.manual_chat_fixture` 可打开标注为模拟数据的测试窗口。

主要模块：`models.py` 配置与文件管理；`native.py` Windows 坐标/窗口检查；`selector.py` 区域选择；`capture.py` 采集与记录；`pdf_export.py` PDF 排版；`ui.py` 桌面界面与后台线程。

## 离线授权（V1.3）

- 首次启动显示本机机器码。客户把机器码发给授权管理员，管理员通过 `授权管理工具/聊天软件截屏助手授权管理器.exe` 生成授权码或 `.license` 文件；客户粘贴或导入后激活。
- 授权使用 3072 位 RSA-PSS/SHA-256 签名，绑定 Windows 机器码，可设永久或到期日期。授权内容被修改、复制到另一台电脑、超过有效期或检测到明显的系统日期回拨时拒绝运行。
- 主程序只包含公钥，在启动、开始采集和生成 PDF 前复核授权。授权文件保存在 `%LOCALAPPDATA%\EvidenceCapture\license.json`，时钟状态经 Windows DPAPI 保护。
- `聊天软件截屏助手授权管理器.exe` 及 `license_private.pem` 包含或持有签发私钥，**只能由软件所有者保管，不得与主程序一起分发**。客户只应收到 `聊天软件截屏助手.exe` 和为其签发的授权码或 `.license` 文件。私钥应离线备份；私钥丢失后无法为现有公钥版本继续签发授权。
- 离线授权可有效阻止直接复制和伪造授权，但任何完全运行在客户电脑上的软件都不能保证绝对无法被逆向或修改。更高强度需要代码签名证书、原生编译/商业混淆，以及由服务端定期验证授权；当前版本不联网，也不上传机器信息。

## GitHub 仓库注意事项

本项目按 GNU GPL v3 许可证公开，使用、修改和分发时须遵守 `LICENSE`。`.gitignore` 已排除私钥、授权码、实际聊天截图、输出目录、打包 EXE、校验文件和授权管理器成品。提交前应执行 `git status`，确认没有 `license_private.pem`、`.license`、`output` 或真实聊天内容。仓库中的授权测试会在内存中临时生成测试密钥，不依赖生产私钥。

主程序的生产公钥必须保留在源码中用于验证签名，这不是秘密。生产私钥只存在于本机 `license_admin/license_private.pem` 和授权管理器成品中；克隆仓库后可以开发、测试并构建主程序，但没有私钥不能签发生产授权，也不能构建可用的授权管理器。

公开源码会降低本地授权校验被定位和删除的难度。RSA 签名仍能阻止伪造或篡改授权文件，但不能阻止他人修改公开源码后重新构建未授权版本。若授权保护优先，应只公开使用说明或编译后的发行包，并保留核心授权校验源码；更强方案需要服务端在线验证。

打包配置排除开发环境 PATH 中可能混入的 Poppler/Conda ICU DLL，使用 Windows 自带 ICU，避免 QtCore 启动时的导入冲突。系统要求参见 [Qt Windows 支持说明](https://doc.qt.io/qt-6/windows.html)，ICU 来源参见 [Microsoft ICU 文档](https://learn.microsoft.com/en-us/windows/win32/intl/international-components-for-unicode--icu-)。
